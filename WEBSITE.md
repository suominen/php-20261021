# Website plan — `https://kimmo.cloud/php-20261021/`

Publish the PHP2Shell tracker (CVE-2026-109618, CVE-2026-109619) as a
single-page static site, generated by **Hugo** locally and rsync'd to a
personal nginx server (`haig`). The repo was cloned from the archived
PHP 2026-09-24 tracker (`~/src/php-20260924`), which was itself seeded
from `~/src/cve-tracker-template` (`skeleton/` plus the `package/`
overlay); the table layout follows the template's current merged
*Patch status* table, as the nginx tracker (CVE-2026-97205) does.

## Architecture

- **Source repo:** `github.com/suominen/php-20261021` (this repo).
- **Generator:** Hugo ≥ 0.146.0 (standard edition). Run locally; nothing
  built in CI.
- **Source layout:** Hugo project under `site/`. The tracker is a single
  page at `site/content/_index.md`.
- **Theme:** PaperMod, integrated as a Hugo Module (no submodule). See
  `site/hugo.toml` and `site/go.mod`.
- **Dev environment:** Nix flake (`flake.nix`) provides everything the
  build, banner, publish, and lookup recipes call (Claude Code itself
  excepted). Auto-activates via `.envrc` with direnv.
- **Build:** `make build` → `hugo --minify --gc --cleanDestinationDir`,
  output in `site/public/`.
- **Publish:** `make dist` → `rsync -avz --delete site/public/`
  → `haig:/php-20261021/`, which the server's restricted rsync
  resolves to `~/.www/sites/kimmo.cloud/htdocs/php-20261021/`.
- **Web server:** existing nginx vhost on `kimmo.cloud` serves
  `htdocs/php-20261021/` directly at the URL path `/php-20261021/`.
  TLS, redirects, and certbot are managed by the host, not by this
  repo.
- **DNS:** unchanged. `kimmo.cloud` already resolves to the haig server.

## Naming

The tracker follows a release event fixing two CVEs that share a
nickname. The slug is the upstream project plus the release date, as
for the previous PHP tracker; the nickname, PHP2Shell, leads the title.
The slug is lowercase everywhere, so the repo, URL, module path,
systemd units, and banner share one spelling.

- repo: `~/src/php-20261021`, `github.com/suominen/php-20261021`
- Go module path: `github.com/suominen/php-20261021/site`
- URL: `https://kimmo.cloud/php-20261021/`
- systemd units: `php-20261021-tracker-update.{service,timer}`
- banner: `site/assets/php-20261021-tracker.svg` →
  `site/static/php-20261021-tracker.png`
- title: "PHP2Shell (CVE-2026-109618, CVE-2026-109619) — unauthenticated
  PHP RCE"
- front-page entry: `CVE-2026-109618, CVE-2026-109619 &mdash;

## Decisions

- **Hosting:** own nginx on `haig`, *not* GitHub Pages. Same as the
  sibling trackers.
- **URL / slug:** `https://kimmo.cloud/php-20261021/` — the release
  date, matching `php-20260924`, while the title leads with the
  PHP2Shell nickname both CVEs are reported under.
- **Theme integration:** Hugo Modules. **Theme:** PaperMod.
- **Canonical source:** `site/content/_index.md`.
- **The template's merged table, not php-20260924's.** The previous
  PHP tracker used `PHP | Package | Fixed since | Status` with no
  upstream rows and sticky version cells. The user chose the
  template's current layout instead: `Current version | First fixed |
  Fixed since | Status`, upstream `PHP` rows first, the PHP branch in
  the *Release* cell, and the branch's threshold in each vulnerable
  row's Status note (`needs 8.4.27`). *Current version* is live, so a
  reader sees what a release ships today, not only what first fixed
  it.
- **One verdict for both CVEs.** A row is Fixed only when it carries
  both fixes; there is no column per CVE. Every supported branch is
  affected by both, and PHP ships them as one Core change.
- **Exposure is prose, not a verdict.** Which SAPI serves PHP and the
  configuration mitigations decide how reachable the bugs are, but
  PHP's advisories call every configuration change incomplete and no
  distro ships a default that removes the bug, so there is no
  *Mitigated* verdict.
- **No rows for end-of-life PHP.** 8.1 and older are vulnerable and get
  no releases, only minimal source backports for 7.4, 8.0, and 8.1;
  the tracker says so in the Summary and the `### PHP` prose rather
  than carrying rows no tracked distribution ships.
- **No `php82` row on nixpkgs `master`.** It was removed there on the
  release day, before the tracker was seeded; the channels still
  carrying it keep their rows until they drop it.
- **The PHP release is read, not run.** `scripts/debian-versions`
  reads the branch from `php-defaults`' `PHP_DEFAULT_VERSION` and the
  release from each package's changelog; pkgsrc and nixpkgs keep all
  branches' versions in one file each, which the other two helpers
  read.
- **Dates are derived, not observed.** A *Fixed since* date comes from
  the source that shipped the fix — php.net's release index, the
  Debian changelog or snapshot.debian.org, the pkgsrc `phpversion.mk`
  history, or, for NixOS, `scripts/nixos-first-shipped`.
- **Distro scope:** intentionally narrow, as in the sibling trackers —
  Debian sid / forky / 13 / 12; the NixOS channels (`nixos-unstable`,
  `nixos-unstable-small`, `nixos-26.05`, `nixos-26.05-small`),
  `nixpkgs-unstable`, and the ungated `master` and `release-26.05`
  branches; pkgsrc `pkgsrc-current` and `pkgsrc-2026Q3` — each with
  every PHP branch it ships. RHEL family (including Remi's
  repository), Amazon Linux, Ubuntu, Arch, Fedora, and Proxmox are out
  of scope.
- **Automated maintenance:** a user-level systemd timer
  (`systemd/php-20261021-tracker-update.timer`, twice daily at
  `05:50` and `17:50` — a slot no other tracker uses) runs
  `scripts/auto-update` with `scripts/auto-update-prompt.txt`,
  committing onto the `auto-update` branch only. Merges into `main`
  are manual. Twice daily rather than php-20260924's once-daily, given
  that exploitation was reported before the release.

## Risks & gotchas

- **Row count.** One row per release and PHP branch makes a long
  table (43 rows at seed, 27 of them NixOS/nixpkgs). Branch changes
  (a distribution adding 8.5 or dropping 8.2) add or freeze rows;
  `CLAUDE.md` § "When a distribution changes branch" has the rules.
- **Anchor drift.** The tracker links internally to `#who-is-exposed`
  and `#mitigation`; don't rename those headings casually.
- **Subpath baseURL.** `baseURL = "https://kimmo.cloud/php-20261021/"`
  must include the trailing slash and the path component.
- **`.cleanDestinationDir`** wipes `site/public/` before each build.
- **rsync `--delete`** removes server-side files not present in the
  build output.
- **Client-side table tweaks.** `layouts/partials/extend_footer.html`
  rewrites the distribution table in the browser (group heading rows
  per distribution, status-cell tagging). With JavaScript disabled the
  table still renders correctly with the Distribution column visible.
  Rows sharing a distribution must stay contiguous.
- **JS-only sources.** The GitHub advisory pages, the NVD web pages,
  and the NixOS security tracker return nothing to WebFetch; the
  tracker reads the GitHub REST API and the CVE Services API instead.
- **ChangeLog date.** php.net's ChangeLog dates the four releases
  22 Oct 2026, a day after the release index and the advisories; the
  tracker uses 2026-10-21.
- **Security-archive changelogs.** ftp-master's changelog metadata
  covers only the main archive; a `-security` upload's changelog is on
  tracker.debian.org, with `~` and `+` dropped from the version in the
  file name. `scripts/debian-versions` tries tracker.debian.org first.

## Social banner

The OpenGraph / social-preview image is generated from an SVG source:
`site/assets/php-20261021-tracker.svg` (1200×630) is rasterised to
`site/static/php-20261021-tracker.png` by `make banner`, which runs
`resvg`. The PNG is committed so ordinary `make build` / `make dist`
runs need no rasteriser.
